# Workflow｜Human-first SEO Refresh

这个工作流用于所有旧文优化、新文章生成和攻略页重构。

目标不是把文章改成统一 SEO 模板，而是在保留清晰搜索结构的基础上，让内容更像作者本人写出来。

## 1. 输入

每次优化文章前，至少读取：

- 原文 Markdown；
- 相关图片；
- 目标关键词 / GSC 数据；
- 相关产品页；
- 站内可用内链；
- `_ai-harness/project-context/human-first-content-principles.md`；
- `_ai-harness/project-context/personal-experience-bank.md`；
- `_ai-harness/project-context/banned-ai-phrases.md`。

## 2. 判断文章类型

先判断文章属于哪一类：

- 交通型：机场、火车、停车、城市间交通；
- 目的地型：城市、小镇、景点集合；
- 路线型：一日游、多日游、出发地路线；
- 主题型：薰衣草、艺术、葡萄酒、亲子、老人、徒步；
- 产品型：精选路线、包车、小团、定制旅行；
- 游记型：个人体验、路线复盘、客户案例。

不同类型采用不同结构，不要全部套同一个模板。

## 3. 保留原文资产

旧文优化时：

1. 保留原文所有有效信息；
2. 保留原文所有有效图片；
3. 只修正过时、不准确或容易误导的信息；
4. 不在正文中出现“旧文、原文、旧版、此次优化”等编辑痕迹；
5. 尽量保留作者原有判断和生活痕迹。

## 4. 加入作者经验层

每篇文章至少加入 3–5 处作者判断。

优先从 `personal-experience-bank.md` 中调用。

可以加入：

- 我自己会怎么走；
- 我带客人时通常怎么安排；
- 我喜欢或不喜欢的地方；
- 哪些地方值得慢一点；
- 哪些地方如果时间短可以删掉；
- 带老人孩子时的具体调整；
- 旺季、淡季、天气不好时的处理方式。

如果经验库没有对应内容，不要编造。可以写成更谨慎的观察语气。

## 5. 语言处理

语言要：

- 口语化；
- 清楚；
- 有一点散文化；
- 允许短句和不完全对称的节奏；
- 像当地朋友认真解释；
- 不要像旅行社广告；
- 不要像百科；
- 不要像 AI 生成的标准答案。

避免：

- 过度整齐；
- 强行三点并列；
- 每段都像总结；
- 抽象形容词堆叠；
- 公式化 CTA；
- AI 口癖。

## 6. SEO / AEO 保留方式

SEO / AEO 仍然重要，但不能压过人味。

必须做到：

- 标题和 description 有搜索意图；
- 首屏回答核心问题；
- H2 层级清楚；
- 表格不过度复杂；
- FAQ 回答真实问题；
- 内链自然；
- CTA 和用户意图匹配；
- 不为了关键词牺牲阅读体验。

## 7. CTA 规则

CTA 不要全部导向“包车”。

根据文章类型选择：

- 交通型：咨询机场接送 / 判断路线衔接；
- 目的地型：查看相关路线 / 发给我判断是否值得安排；
- 路线型：填写行程需求 / 查看精选路线；
- 主题型：继续看攻略 / 咨询定制路线；
- 产品型：在线咨询 / 填写行程需求 / 查看适合人群。

CTA 文案要像真人邀请，不像销售逼单。

## 8. 输出前检查

每次输出前检查：

- 是否至少有 3–5 处作者经验；
- 是否有 AI 味表达；
- 是否每篇结构都长得一样；
- 是否自然提到作者背景；
- 是否存在过度营销；
- 是否有站内链接；
- 是否有对应产品或定制入口；
- 是否保留原文有效图片；
- 是否适合手机阅读；
- 是否标题层级清晰。

## 9. 输出方式

默认生成新 draft，不直接覆盖正式文章。

输出时说明：

- 新文件路径；
- 预览 URL；
- 标题和 description 字数；
- 保留图片数量；
- 新增或优化的内链；
- 作者经验加入位置；
- SEO / AEO 调整；
- AI 味表达检查结果。
